# 音频编创

## 范围

音频编创（OHAudioSuite，AudioKit）通过 C API `libohaudiosuite.so`（系统能力 `SystemCapability.Multimedia.Audio.SuiteEngine`）提供引擎、管线、节点编排、效果处理、离线编辑、实时预览、PCM 格式转换和云端算法资源下载能力。实时算法处理在应用进程内完成，云端模型资源的下载与安装由独立 SA 3015（`audio_suite_server`）承载。

本主题是 audio_suite 知识库的总览和导航；各能力的详细规格见下方主题文档。实时音频引擎（HPAE）和在线音效见 [音频引擎.md](../audio_engine/音频引擎.md)，播放与录制会话见 [音频播放.md](../audio_stream/audio_renderer/音频播放.md) 和 [音频录制.md](../audio_stream/audio_capturer/音频录制.md)。

## 版本与接口边界

OHAudioSuite 的能力按 API 版本分批开放，公开接口与系统接口（头文件标注 `@systemapi`）必须分开描述。

| API 版本 | 新增能力 | 接口性质 |
| --- | --- | --- |
| 22 | 引擎、管线、节点、均衡器、降噪、声场、音源分离、声音美化、环境效果、混音；离线编辑与实时预览 | 公开 |
| 23 | 空间渲染、传统变声、通用变声、变速变调；实时预览支持全部效果节点 | 公开 |
| 26.0.0 | PCM 格式转换器；运行时快照；元数据渲染帧、系统节点与系统节点参数；云端算法资源下载管理 | 转换器与 `OH_AudioSuite_PrintInfo()` 公开，其余 `@systemapi` |
| 26.0.1 | 批量查询特性安装状态、下载状态和新版本信息 | `@systemapi` |
| 26.1.0 | 扩展格式转换器（`ConverterCreateEx`、`ConverterGetMinInOutSizes`、`ConverterDirectProcess`、`ConverterGetDelaySize`、`ConverterFlush`） | `@systemapi` |

接口边界：

- 接口声明以 `interface_sdk_c/multimedia/audio_framework/audio_suite_engine/` 为准，只有列入 `ohaudiosuite.ndk.json` 的符号才会随 SDK 发布。本仓 `interfaces/kits/c/audio_suite/` 是同一组头文件的实现仓副本，变更时两仓同步。
- 非系统应用调用 `@systemapi` 接口按契约返回 202。下载服务与扩展转换器在调用入口做系统应用校验；引擎侧系统节点和元数据渲染入口在实现仓 master 上尚未见同等校验，改动这些入口时需先确认权限策略。
- 实现仓 master 与 SDK master 的接口代差按具体能力核对：按已交付能力描述时以实现仓 master 为准，按接口契约描述时以 SDK master 头文件为准。
- 系统节点编号存在存量差异：SDK master 的 302 为声音美化，实现仓 master 的 302 仍为 MusicMaster（音乐母带）。跨仓修改时需同时核对 `native_audio_suite_base.h` 与 `audio_suite_base.h` 的枚举映射。

## 架构总览

- 引擎是能力入口，管理管线和节点；实现仓 master 的 `OHAudioSuiteEngine` 为进程级单例。
- 管线是执行单元，承载节点组网和渲染状态；每条管线至少 1 个输入节点，有且只有 1 个输出节点。
- 节点分为输入、效果和输出；节点必须属于某条管线，不能独立工作。
- 数据流采用反向驱动：应用调用 `RenderFrame()`/`MultiRenderFrame()`/`MetaRenderFrame()` 后，输出节点逐级向上游请求数据，最终由输入节点回调向应用取 PCM 数据。
- 离线编辑（编辑模式）由应用逐帧驱动；实时预览（实时模式）由应用在 `OH_AudioRenderer` 写回调中驱动。
- 生命周期顺序：创建引擎 → 创建管线 → 创建并连接节点 → 启动管线 → 逐帧渲染 → 停止管线 → 销毁节点/管线/引擎；释放顺序相反。

## 关键限制汇总

| 对象 | 限制 |
| --- | --- |
| 引擎 | 实现仓 master 为进程级单例 |
| 管线 | 进程内最多 10 条 |
| 输入节点 | 每管线最多 15 个 |
| 输出节点 | 每管线有且只有 1 个 |
| 效果节点 | 每管线最多 15 个 |
| 混音节点 | 每管线最多 3 个 |
| 音源分离节点 | 每管线最多 1 个 |
| 系统节点参数 | 1 至 8192 字节 |
| 转换器回调 | 单次最多 400 KB；输出缓冲至少一个采样帧 |
| 转换器 DirectProcess | 单次输入不超过 1000 ms |
| 下载批量接口 | 单次最多 128 个特性；名称长度小于 256 字节 |

## 错误码规格

| 值 | 错误码 | 含义 |
| --- | --- | --- |
| 0 | `AUDIOSUITE_SUCCESS` | 成功 |
| 1 | `AUDIOSUITE_ERROR_INVALID_PARAM` | 参数无效 |
| 2 | `AUDIOSUITE_ERROR_INVALID_STATE` | 状态异常 |
| 3 | `AUDIOSUITE_ERROR_SYSTEM` | 系统错误 |
| 4 | `AUDIOSUITE_ERROR_UNSUPPORTED_FORMAT` | 格式不支持 |
| 5 | `AUDIOSUITE_ERROR_ENGINE_NOT_EXIST` | 引擎不存在 |
| 6 | `AUDIOSUITE_ERROR_PIPELINE_NOT_EXIST` | 管线不存在 |
| 7 | `AUDIOSUITE_ERROR_NODE_NOT_EXIST` | 节点不存在 |
| 8 | `AUDIOSUITE_ERROR_UNSUPPORTED_CONNECT` | 节点连接不支持 |
| 9 | `AUDIOSUITE_ERROR_UNSUPPORTED_OPERATION` | 操作不支持 |
| 10 | `AUDIOSUITE_ERROR_CREATED_EXCEED_SYSTEM_LIMITS` | 创建数量超过系统限制 |
| 11 | `AUDIOSUITE_ERROR_REQUIRED_PARAMETERS_MISSING` | 必填参数缺失 |
| 12 | `AUDIOSUITE_ERROR_TIMEOUT` | 操作超时 |
| 13 | `AUDIOSUITE_ERROR_MEMORY_ALLOC_FAILED` | 内存分配失败 |

转换器使用独立的 `OH_AudioConverter_Result`：0 至 8 分别表示成功、参数无效、格式不支持、系统错误、内存分配失败、输出缓冲不足、实例未初始化、回调无效和回调未设置；26.1.0 起增加 202（非系统应用）和 6800104（操作不支持）。下载接口使用 `AUDIOCOMMON_RESULT_*` 错误码（成功、参数无效、系统错误、服务死亡、状态不允许、网络条件不满足等）。

## 依赖关系

只列跨部件依赖；`audio_framework` 组件内部的引擎、音频服务、工具库等依赖不在此展开。

- 接口声明：依赖 `interface_sdk_c` 仓的 `audio_suite_engine` 头文件和 `ohaudiosuite.ndk.json`；本仓 `interfaces/kits/c/audio_suite/` 需与其同步。
- HDI：系统节点经离线音效链使用 Audio Effect HDI 1.0（`IEffectModel`/`IEffectControl`），接口定义和 `libeffect_proxy_1.0` 来自 `drivers_interface` 仓的 `drivers_interface_audio` 组件；`libohaudiosuite.so` 和 `audio_suite` 库不直接链接 HDI。
- 基础系统组件：`samgr`、`ipc`、`safwk`、`eventhandler`、`common_event_service`、`hisysevent`、`hitrace`、`hilog`、`c_utils`、`libxml2`、`ffrt`、`init`、`bounds_checking_function`、`media_foundation`（media_monitor）。
- 后台下载可选组件：`netmanager_base`（Wi-Fi）、`battery_manager`（充电/电量）、`screenlock_mgr`（锁屏）；未集成时对应条件判断返回 true。
- 算法库：按 `/system/etc/audio/audio_suite_capabilities.xml` 的 `soName` 加载厂商算法库（`libimedia_sws`、`libimedia_vqe_ainr`、`libaudio_aiss_intergration`、`libaudio_voice_morph`、`libaudio_voice_morph_bgm`、`libaudio_variable_speed`、`libaudio_pitch_change`、`libspace_render`、`libhvs_rendering`）；混音节点不依赖算法库。
- 云端模型：模型资源由云端下发并受网络与后台下载条件约束；下载、安装和校验细节见 [云资源下载.md](cloud_resource_download/云资源下载.md)。

## 约束与常见误区

- 节点不能脱离管线和引擎单独使用；不要把 builder 当成节点句柄，也不要在节点创建后继续修改 builder 的节点类型而不调用 `Reset()`。
- 效果节点不能设置输入输出格式，其输出格式由节点类型固定；修改效果节点格式返回 `AUDIOSUITE_ERROR_UNSUPPORTED_OPERATION`。
- 管线停止状态下不能渲染；`finishedFlag` 为 true 后也不能继续渲染；停止管线会清空缓存但不会断开连接。
- 管线数量、输入/输出节点数量、混音和音源分离数量均为硬限制，超过时返回 `AUDIOSUITE_ERROR_CREATED_EXCEED_SYSTEM_LIMITS`。
- HOA 空间渲染节点的前置节点必须是 HOA 格式输入节点，连接不合法时错误到 `StartPipeline()` 才暴露。
- 采样率 11025 Hz 必须按 40 ms 计算帧长；其他采样率按 20 ms 帧长计算，并需与 Renderer 回调保持一致。
- 不要把 `@systemapi` 的下载、系统节点和元数据渲染接口当作三方应用可用能力；也不要把某个产品支持的节点类型写成所有设备的固定能力。
- 云端下载只负责模型资源，不代表算法节点已可用；节点创建仍需通过 `IsNodeTypeSupported()` 检查。
- 运行期改图可能丢数据；优先在停止状态完成拓扑调整，运行期开关节点使用 `BypassEffectNode()`。

## 安全与隐私

- 所有跨接口传入的指针、长度、数组容量和枚举值必须校验；缓冲区容量与真实分配大小由调用方保证一致。
- 系统接口必须校验调用者身份，非系统应用返回 202；批量下载接口校验特性名白名单、数量上限和输出数组容量。
- 用户音频、分离结果、变声结果和中间缓存均按敏感数据处理，日志、快照和转储不得包含原始 PCM、用户内容或可识别个人的音频特征。
- 明确缓冲区所有权：输入回调的数据在本次渲染调用返回前有效；转换器回调的数据在 `Process()` 返回前有效。
- 输入帧和输出帧不得指向同一块内存；共享缓冲区、文件描述符和下载路径需做边界校验。
- 失败、取消、超时和服务退出后不得残留未释放的管线、节点、转换器或下载任务；模型资源安装路径和完整性由服务侧校验。
