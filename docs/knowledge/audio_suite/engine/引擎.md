# 引擎

## 范围

引擎是 OHAudioSuite 的能力入口，对应 `OH_AudioSuiteEngine` 句柄，负责创建和销毁管线、持有节点，并分发渲染与参数接口。引擎不选择输出设备、不申请音频焦点，也不直接创建播放流；设备、焦点和播放链路由音频策略与 Renderer/Capturer 负责。

管线的模式、状态和配额见 [管线.md](../pipeline/管线.md)，节点类型和效果参数见 [节点.md](../node/节点.md)。

## 设计规格

### 实例模型

- 实现仓 master 的 `OHAudioSuiteEngine` 为进程级单例：`OH_AudioSuiteEngine_Create()` 成功初始化单例，重复创建返回 `AUDIOSUITE_ERROR_INVALID_STATE`；未创建时调用 `OH_AudioSuiteEngine_Destroy()` 同样返回该错误。
- `Destroy()` 调用内部清理流程，释放该引擎持有的全部管线和节点；销毁后原管线、节点句柄失效。
- 当前实现不支持同进程多引擎实例。需要并行处理多个音频流时，使用多条管线，或在应用侧拆分处理任务。

### 生命周期

- 标准顺序：`Create` → `CreatePipeline` → `CreateNode`/`ConnectNodes` → `StartPipeline` → `RenderFrame`/`MultiRenderFrame`/`MetaRenderFrame` → `StopPipeline` → `DestroyNode`/`DestroyPipeline` → `Destroy`。
- 释放顺序与创建顺序相反；销毁管线会释放其节点，销毁引擎会清理所有管线和节点。
- 管线数量受进程级上限约束（最多 10 条，见 [管线.md](../pipeline/管线.md)）。

### 能力与构建开关

- 节点能力由 `/system/etc/audio/audio_suite_capabilities.xml` 配置；混音节点恒支持，其余节点需通过 `OH_AudioSuiteEngine_IsNodeTypeSupported()` 检查。
- `audio_framework_feature_audiosuite_support`（默认 false）控制 `libohaudiosuite`、SA 3015、SA profile、init 配置和测试；`audio_framework_feature_audiosuite_format_convert_support` 控制转换器实现单独编入 `audio_suite`。

### 运行时快照

- `OH_AudioSuite_PrintInfo()` 可输出引擎或单条管线的节点状态；`fd` 小于 0 时写入日志，否则以追加方式写入文件。
- 快照不包含 PCM 数据、文件描述符或节点地址。

### 并发与实时调度

- 引擎和管线的内部互斥锁串行化创建、销毁、连接和参数变更；同一管线的渲染接口不应并发调用，也不要在渲染回调中重入引擎接口。
- 实时预览模式通过 AudioWorkgroup 提升渲染线程优先级，帧周期为 20 ms，具体约束见 [实时预览.md](../realtime_preview/实时预览.md)。

## 约束与常见误区

- 不要把引擎句柄当作管线或节点句柄；三类句柄的生命周期相互独立。
- 重复 `Create` 或未创建就 `Destroy` 都返回 `AUDIOSUITE_ERROR_INVALID_STATE`，不要用重试规避。
- 引擎销毁会级联释放管线和节点，调用方不得继续持有或使用旧句柄。
- 引擎单例不代表渲染线程安全；并发渲染需要应用侧串行化或拆分管线。

## 安全与隐私

- 接口入口校验句柄非空、句柄与当前单例实例一致，并拒绝已销毁对象的句柄。
- 日志和快照不得输出节点地址、管线地址或用户音频内容。
- 销毁引擎前应确保没有线程仍在渲染；应用应先停止管线并等待回调返回。
